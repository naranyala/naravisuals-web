# Generated Output

The build script (`scripts/build-docs.mts`) scans all `.md` files in `docs/` and generates TypeScript data files under `src/generated/`. These files contain the entire documentation site as static data -- no runtime API calls are needed.

## Directory Structure

```:desc=Generated directory structure
src/generated/
├── index.ts          # Barrel export -- single entry point
├── sidebar.ts        # sidebarData array with category/item tree
├── types.ts          # DocEntry interface definition
├── clipboard.ts      # copyCode helper (static, NOT regenerated)
└── docs/
    ├── index.ts      # Re-exports all doc entries
    └── *.ts          # One file per markdown document
```

## File Breakdown

### index.ts

The barrel export re-exports everything from the submodules:

```ts:desc=TypeScript code example
// AUTO-GENERATED -- DO NOT EDIT.
import "./clipboard.ts";

export { sidebarData } from "./sidebar.ts";
export type { SidebarItem, SidebarDocItem, SidebarCategoryItem } from "./sidebar.ts";
export { allDocs } from "./docs/index.ts";
export type { DocEntry } from "./types.ts";
```

Import from this single entry point in application code:

```ts:desc=TypeScript code example
import { allDocs, sidebarData, type DocEntry } from "./generated";
```

### sidebar.ts

Contains the sidebar data as a tree of category and doc items:

```ts:desc=TypeScript code example
export interface SidebarDocItem {
  type: "doc";
  id: string;
  label: string;
  slug: string;
  category?: string;
  date?: string;
}

export interface SidebarCategoryItem {
  type: "category";
  label: string;
  link?: { type: string; id: string };
  items: SidebarDocItem[];
}

export type SidebarItem = SidebarDocItem | SidebarCategoryItem;

export const sidebarData: SidebarItem[] = [ /* ... */ ];
```

Categories are sorted by their folder numeric prefix (e.g., `01-getting-started` before `02-guides`). Within each category, docs are sorted by `sidebar_position`.

### types.ts

Defines the `DocEntry` interface that represents a single documentation page:

```ts:desc=TypeScript code example
export interface DocEntry {
  id: string;
  slug: string;
  title: string;
  sidebar_label: string;
  sidebar_position: number;
  category: string;
  description: string;
  content: string;
  toc: { value: string; id: string; level: number }[];
  date?: string;
  author?: string;
  tags?: string[];
  section: "docs" | "blog";
  metadata: Record<string, string | string[]>;
  ast?: any[];
}
```

Key fields:

| Field | Description |
|---|---|
| `id` | Unique identifier (equals `slug`) |
| `slug` | URL path segment, e.g. `"guides/build-system"` |
| `content` | HTML string (marked output + plugin transformations) |
| `toc` | Table of contents extracted from `##` and `###` headings |
| `metadata` | Arbitrary frontmatter fields beyond the known schema |
| `ast` | Raw marked.js token array (used only for debugging) |

### clipboard.ts

A static helper that provides the global `copyCode()` function for code block copy buttons. Unlike other files in `src/generated/`, this file is **not** regenerated by the build script:

```ts:desc=TypeScript code example
window.copyCode = (btn: HTMLElement) => {
  const codeBlock = btn.closest(".code-block");
  if (!codeBlock) return;
  const code = codeBlock.querySelector("pre code");
  if (!code) return;
  const text = code.textContent || "";
  navigator.clipboard.writeText(text).then(() => {
    const original = btn.textContent;
    btn.textContent = "Copied!";
    setTimeout(() => { btn.textContent = original; }, 2000);
  });
};
```

It is imported via side-effect in `index.ts` so it executes once at app startup.

### docs/index.ts and docs/*.ts

Each markdown file gets its own `.ts` file under `docs/`. The filename is derived from the slug using `slugToVarName`:

```ts:desc=TypeScript code example
// slug: "guides/build-system" -> var name: "guides_build_system"
// slug: "getting-started/project-overview" -> "getting_started_project_overview"
```

The barrel file re-exports all doc entries and assembles them into `allDocs`:

```ts:desc=TypeScript code example
export { welcome, getting_started_project_overview, /* ... */ };

export const allDocs: DocEntry[] = [
  welcome,
  getting_started_project_overview,
  // ...
];
```

## Consumption Flow

```mermaid:desc=Generated output consumption flow diagram
flowchart lr
    A["docs/*.md files"] --> B["build-docs.mts"]
    B --> C["src/generated/docs/*.ts"]
    B --> D["src/generated/sidebar.ts"]
    B --> E["src/generated/types.ts"]
    C --> F["src/generated/docs/index.ts allDocs"]
    D --> G["src/generated/index.ts barrel"]
    E --> G
    F --> G
    G --> H["App.tsx imports allDocs"]
    H --> I["finds current doc by slug"]
    I --> J["DocViewer renders content HTML"]
```

In `App.tsx`, the current document is resolved from the URL:

```ts:desc=TypeScript code example
const resolveSlug = (): string => {
  const path = services.router.getCurrentPath();
  if (path === "/" || path === "") return "welcome";
  if (path.startsWith(`/${services.config.routes.docs}/`)) {
    return path.replace(`/${services.config.routes.docs}/`, "");
  }
  return allDocs[0]?.slug || "welcome";
};

const currentDoc = allDocs.find((d) => d.slug === currentSlug) ?? null;
```

The HTML content string is passed directly to `DocViewer`, which inserts it via `dangerouslySetInnerHTML`.

## When Regeneration Triggers

The generated output is produced by running `bun run build:docs` (or `bun run scripts/cli.mts docs`). Regeneration is triggered when:

- **`.md` files change** -- any addition, deletion, or modification in `docs/` or `blog/`
- **Build script runs** -- via CLI command `docts docs` or `bun run build:docs`

Regeneration is **not** triggered by:

- React component changes (`src/*.tsx`)
- CSS/style changes (`src/styles/*.css`)
- Configuration changes (`rspack.config.ts`, `tsconfig.json`)

The build pipeline reads all `.md` files, parses frontmatter, runs markdown plugins through `marked`, applies Shiki syntax highlighting, and writes the output files.

## Slug and Filename Conversion

Two utility functions in `build-docs.mts` handle name conversion:

```ts:desc=TypeScript code example
// Converts slug to a safe TypeScript variable name
function slugToVarName(slug: string): string {
  return slug.replace(/\//g, "_").replace(/-/g, "_");
}
// "guides/build-system" -> "guides_build_system"

// Converts slug to a kebab-case filename
function slugToFilename(slug: string): string {
  return slug.replace(/\//g, "-");
}
// "guides/build-system" -> "guides-build-system.ts"
```

The variable name is used for the export in `docs/index.ts`, while the filename determines the actual file on disk.
