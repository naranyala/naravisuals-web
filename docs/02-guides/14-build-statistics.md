# Build Statistics

The build system now provides **detailed statistics** about your documentation content during the build process. This helps you understand the composition and scale of your documentation.

---

## What Statistics Are Tracked?

### 1. Codeblocks

The build system counts all codeblocks across your documentation and tracks:

- **Total count** - Number of codeblocks in all docs
- **Language distribution** - Breakdown by programming language
- **Percentage breakdown** - Visual bar chart showing language usage

### 2. Admonitions

The admonitions plugin tracks all `:::type` callout blocks:

- **Total count** - Number of admonition blocks
- **Type distribution** - Breakdown by type (note, tip, warning, danger, etc.)
- **Percentage breakdown** - Visual representation of type usage

Statistics are automatically displayed when you run:

```bash:desc=Command to build documentation and display statistics

bun run build

## How It Works

### Statistics Pipeline

```mermaid:desc=Flowchart showing how build statistics are collected: AST tokens are parsed, filtered for code and admonition types, aggregated by language/type, and displayed with visual bar charts.
flowchart LR
    subgraph Parse["Parse Phase"]
        A["Markdown\nFiles"] --> B["marked.parse\nGenerate AST"]
        B --> C["AST Tokens\nFlat Array"]
    end

    subgraph Collect["Collection Phase"]
        C --> D[Filter code tokens]
        C --> E["Find admonition\nHTML classes"]
    end

    subgraph Aggregate["Aggregation Phase"]
        D --> F["Group by\nlanguage"]
        E --> G["Group by\ntype"]
    end

    subgraph Display["Display Phase"]
        F --> H["Codeblock Stats\nBar chart"]
        G --> I["Admonition Stats\nDistribution"]
    end

    style Parse fill:#e1f5ff
    style Collect fill:#fff4e1
    style Aggregate fill:#e8f5e9
    style Display fill:#f3e5f5
```

### Codeblock Detection

Codeblocks are detected from the **AST (Abstract Syntax Tree)** tokens generated by the `marked` markdown parser:

```typescript:desc=Code from build script showing how codeblock tokens are filtered from the AST
// From scripts/build-docs.mts
const codeTokens = doc.ast.filter((t: any) => t.type === "code");
```

The language is extracted from the codeblock's info string:

```markdown:desc=Examples showing different ways to specify codeblock language and metadata
```typescript        ← Language: "typescript"
```typescript:title=src.ts  ← Language: "typescript" (metadata ignored)
```                    ← Language: "text" (default)
```

### Admonition Detection

Admonitions are detected by searching for the generated HTML class pattern:

```typescript:desc=Regex pattern to find admonition HTML elements in the generated content
const admonitionMatches = doc.content.match(/class="admonition admonition-(\w+)"/g);
```

This works because the admonitions plugin converts `:::note` blocks into:

```html:desc=HTML structure generated by admonitions plugin with heading, icon, and content sections
<div class="admonition admonition-note">
  <div class="admonition-heading">ℹ️ Note</div>
  <div class="admonition-content">...</div>
</div>
```

## Why Statistics Matter

### 1. Documentation Quality

- **High codeblock count** → Technical documentation with lots of examples
- **Balanced admonitions** → Good use of callouts for important information
- **Language diversity** → Multi-language code examples

### 2. Performance Optimization

Understanding content composition helps optimize:

- **Syntax highlighting** - Most-used languages can be pre-loaded
- **Bundle size** - Know which Shiki languages are actually needed
- **Rendering** - Heavy admonition usage might need CSS optimization

### 3. Content Planning

Statistics help you understand:

- Which languages your documentation focuses on
- Whether you're using admonitions effectively
- The scale and scope of your documentation

## Interpreting Statistics

### Healthy Documentation Profile

A well-balanced technical doc site might show:

```text:desc=Example of healthy documentation statistics showing balanced language and admonition distribution
🔲 Codeblocks: 50-200
   - Primary language (50-70%)
   - Shell commands (15-25%)
   - Configuration (5-15%)

📢 Admonitions: 10-50
   - Mix of note/tip (60%)
   - Some warnings (25%)
   - Few danger/caution (15%)
```

### Optimization Tips

- **Reduce `txt` language** - Tag all codeblocks with proper language
- **Balance admonitions** - Don't overuse any single type
- **Track growth** - Monitor statistics as docs expand

## Troubleshooting

### Statistics Show Zero Codeblocks

**Possible causes:**
- Markdown files not in `docs/` directory
- Files not ending in `.md`
- Build script not running

**Fix:**
```bash:desc=Commands to verify docs exist and run the build script manually
# Verify docs exist
ls docs/*.md

# Run build manually
bun run scripts/build-docs.mts
```

### Admonitions Not Counted

**Possible causes:**
- Admonitions plugin not enabled
- Incorrect `:::type` syntax
- Admonitions inside codeblocks

**Fix:**
```markdown:desc=Example showing correct admonition syntax versus incorrect usage inside codeblocks
# Correct syntax
:::note
This is a note.
:::

# Wrong - putting admonitions inside codeblocks won't count them
# (They'll be treated as literal text, not admonitions)
```
