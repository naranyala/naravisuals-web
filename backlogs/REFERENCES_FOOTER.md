# Article References Panel - Footer Implementation

## Overview

The **Article References Panel** is now positioned at the **very bottom** of each article (after DocFooter) and displays all footnote references `[^index]` with their definitions in a collapsible, expanded-by-default list format.

## What Changed

### Before (DocStatsFooter)
- Showed document statistics (word count, headings, code blocks, etc.)
- Positioned between DocViewer and DocFooter
- Generic metrics, less actionable
- Required parsing rendered HTML

### After (ArticleRefsPanel)
- Shows **only footnote references and definitions**
- Positioned at the **very bottom** (after DocFooter)
- **Expanded by default** for immediate visibility
- Extracts from AST tokens (more accurate)
- List format with numbered entries

## How It Works

### Data Source

The panel extracts footnotes from the **AST tokens** (`currentDoc.ast`) generated by the `marked` parser during build time.

**AST Structure:**
```javascript
[
  { type: "paragraph", text: "Some text[^1]..." },
  { type: "paragraph", text: "[^1]: First footnote definition" },
  { type: "heading", depth: 2, text: "Section" },
  // ...
]
```

### Extraction Process

1. **Walk AST Tokens**
   - Recursively traverse all tokens
   - Check for nested tokens (lists, items, etc.)

2. **Find References**
   - Match pattern: `/\[\^([^\]]+)\]/g`
   - Extract identifier from `[^identifier]`
   - Track in map

3. **Find Definitions**
   - Match pattern: `/^\[\^([^\]]+)\]:\s+(.+)$/`
   - Extract identifier and definition text
   - Link to existing reference or create new entry

4. **Build List**
   - Combine references and definitions
   - Track `hasDefinition` and `hasReference` flags
   - Display in numbered list

### Component Props

```typescript
interface ArticleRefsPanelProps {
  contentHtml: string;        // Rendered HTML (unused now)
  markdownAst?: any[];        // AST tokens from marked parser
}
```

## Footnote Entry Structure

```typescript
interface FootnoteEntry {
  identifier: string;        // "1", "note", "ref", etc.
  referenceText: string;     // "[^1]", "[^note]", etc.
  definitionText: string;    // Actual definition content
  hasDefinition: boolean;    // true if definition exists
  hasReference: boolean;     // true if referenced in text
}
```

## Edge Cases

### Handled Gracefully

✅ **Reference without definition:**
- Shows warning badge "⚠️ No definition"
- Still listed in panel
- Helps identify missing footnotes

✅ **Definition without reference:**
- Listed with `hasReference: false`
- Can be filtered in future
- Helps identify orphaned definitions

✅ **Duplicate references:**
- Deduplicated by identifier
- First occurrence wins
- Prevents clutter

✅ **Empty definitions:**
- Treated as missing definition
- Shows warning badge
- Encourages complete footnotes

✅ **No footnotes:**
- Panel doesn't render at all
- No empty state shown
- Clean UI when not applicable

### Not Handled (Future)
